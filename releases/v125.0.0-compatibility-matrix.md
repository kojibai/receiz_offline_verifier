# Receiz v125.0.0 Compatibility Matrix

V125 is additive. Historical artifacts remain governed by the exact release law under which they were sealed; current readers gain stricter admission and better continuity without rewriting prior truth.

| Surface | v125 authority | Historical compatibility |
|---|---|---|
| Sealed proof objects | Verify the enclosing artifact before extracting or trusting any embedded payload | Original bytes, identifiers, signatures, registries, and release law remain unchanged |
| Kai / KKS | Proof-bearing `KKSv1.0`/KaiSigil coordinates and exact prior heads order authoritative appends | Legacy Chronos projections remain readable but cannot be promoted into KKS authority |
| Chronos | Human-readable projection derived from Kai | Retained for display, import, and compatibility; never used to outrank an admitted Kai coordinate |
| Identity genesis | Earliest verified Identity Record/Seal Kai coordinate wins | Lawful original creation pulses are recovered and preserved; unprovable rows remain explicitly unbound |
| Creation Sigil | Projects the admitted original creation coordinate across profile, wallet, and World | Existing visible Sigils and their creation geometry remain visible |
| Durable local truth | First admission only, then append forever; known proof paints immediately | Existing profile, Showcase, history, pack, card, media, and account continuity remain available without rediscovery |
| Global synchronization | Append, compare-and-swap, distribution, indexing, replay, and recovery | No server, database, or session becomes proof authority |
| Attestation roles | Authorized grantor binds the role; each event carries fresh actor proof | Events valid before a coordinated revocation remain verifiable |
| Evidence | Referenced proof objects are opened and verified before counting | Historical evidence stays governed by its recorded verifier and artifact law |
| Credential lifecycle | Deadline, predecessor lifecycle head, actor proof, evidence, and Kai causality are required | Earlier valid credentials remain inspectable under their original history |
| Settlement | Spendable proof-native Phi projected from sealed proof | Existing sends, market operations, certificates, and ownership history remain valid |
| Reserve | Named legacy funded rail | Existing funded origin, Notes, wires, and Reserve-specific behavior remain intact |
| Custody | One current owner, one spendable membership | Complete provenance and prior ownership remain append-only |
| SDK / MCP / AI Skills | Coordinated exact `125.0.0` graph; compatibility range `>=125.0.0 <126.0.0` | Older coordinated package releases remain historical, not silently relabeled |
| HTTP / OIDC / CORS | Versioned lawful-action routes bind application identity and registered redirect origins | Stable v122/v123/v124 routes remain supported |
| Error semantics | Every non-2xx HTTP response rejects in SDK and MCP | No documented rejection can be misreported as successful tool output |
| Public proof surfaces | Known identity, ownership, media, and history paint without weaker hydration | No settled first paint is replaced by a loading state or duplicate object |
| Release evidence | Package, database, deployment, Git, Docs, and attestation facts are recorded separately | No later release record rewrites earlier evidence |

Serialized runtime-custody brands, self-hashable namespaces, copied domains, filenames, labels, timestamps, and database rows are representations. They cannot cross a process boundary and retain authority without reopening the stronger proof object.
