# Receiz v124.0.3 Regression Lessons — Reality Becomes Infrastructure

Release date: August 25, 2026

**The Production Runtime for Verified Civilization.** Constitutional ruleset `124.0.0` remains unchanged. The governing incident is exact: [Playback Representation Entered the Proof Hot Path](../governance/incidents/2026-08-25-playback-representation-hot-path-regression.md). V124 law did not fail. The implementation boundary failed to keep a representation beneath its source.

Durable proof memory remains first admission only, then append forever. `@receiz/sdk` is the coordinated public verifier and append surface beneath that law, never a substitute for source custody.

## What Regressed

1. V124.0.1 shipped the established Record, Seal, Verify, Append, offline authority, ownership, and PBI primitives.
2. V124.0.2 introduced portable material representations. The breakthrough was real, but automatic playback construction and retained whole-artifact copies entered proof execution paths.
3. Large browser artifacts amplified into source bytes, sealed bytes, state snapshots, `ArrayBuffer` copies, worker-transfer preparation, and playback custody at the same time.
4. Mobile browsers exhausted memory and reloaded. Some UI branches presented the execution failure beneath an invalid/rejected frame, which was a truth downgrade.
5. The repository first restored exact V124.0.1 behavior, then reintroduced only bounded source-first mechanics under the unchanged canonical verifier.
6. The historical audit found additional boundary defects hidden by compilation or small fixtures: a generic bundle cast during reseal, a mismatched Workbench verifier type, large append materialization, PBI authorship composed through an ownership successor, Offline Studio large verification bypassing the streaming path, stale runtime build ordering, and a Profile eager-cover reversal.
7. A final PBI audit traced a separate verifier drift to `8c52fceba` and `60d4eef40`: Workbench rendered an export badge into new PNG pixels after creating a valid PBI successor, retained the predecessor/native ownership basis, and then used a local exception to accept the representation. The standalone offline verifier correctly rejected those rewritten bytes with `continuity_ownership_attestation_mismatch`.

## Why It Regressed

Small images and short videos do not expose simultaneous-copy amplification. A compile-time cast can conceal a malformed authority boundary. A Workbench success can conceal a `/verify` incompatibility if the deployed application is one commit behind. A QR can scan while still carrying the wrong proof class. A settled Profile can visibly finish while eager below-fold resources keep browser navigation open.

Release qualification must therefore combine exact large fixtures, canonical verification, append/PBI descendants, compiler/type checks, both offline verifier distributions, public-route classification, cold browser observation, and dirty-tree/source-digest checks. Passing any one layer cannot overrule contradictory visible or artifact evidence.

## Locked Rules

- Representation never outranks source.
- Source bytes are retained once; optional presentations are derived on demand.
- No assertion may upgrade generic data into a proof bundle.
- No resource exception may become an invalid verdict.
- PBI authorship and ownership transfer must use their distinct canonical successor builders.
- The exact verified PBI descendant is the only exportable proof object; an export representation has no verification exception.
- Every verifier adapter must consume the SDK exact-byte acceptance result, including asset-continuity state, before emitting success.
- The verifier distribution and embedded Offline Studio verifier must remain byte-identical.
- A final compact proof URL may be projected only after it exists; never mutate the source to predict its own completed hash.
- Profile resource containment may not remove settled shells or rediscover known proof truth.
- Working image/audio global sync may not be rewritten to fix video.
- A transient native-image blob may paint immediately, but the carried proof URL must remain capable of reconstructing the image after that blob is released.
- Identity artifacts cannot become Profile Showcase rows through session fallback or display projection.
- Same-profile global publication preserves authenticated owner viewer authority; a public projection cannot temporarily remove owner controls from the settled surface.
- Tests must fail on the exact boundary that caused the incident; they may not ratify the regression.

## Contract Gates

- SDK native-ownership parity vectors fail if current artifact basis, native payload basis, and continuity attestation diverge.
- Workbench small-file and streaming adapters fail if they project base-verifier success before SDK exact-byte acceptance.
- Exact PBI export contracts fail if a badge, canvas, preview, or other representation rewrites the verified descendant.
- Offline Studio and standalone verifier contracts fail on runtime drift, large-file whole-buffer verification, or differing verdicts.
- Coordinated package contracts fail if SDK, MCP capabilities, AI Skills, generated distributions, or release identity diverge.
- Profile contracts fail if native images do not re-project from carried proof URLs, session fallback fabricates showcase originals, or the post-publication handoff temporarily removes the owner's signature control.
- The release freeze remains blocked by contradictory browser/mobile evidence or an unqualified production build.
