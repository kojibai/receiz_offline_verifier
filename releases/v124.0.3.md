**Representation never outranks source.**

- **Source-first large-media execution.** Record, Seal, Verify, Append, PBI authorship, and Export retain one immutable source `File`, hash and verify incrementally, append only a bounded proof trailer, and materialize whole bytes only at an explicit boundary that requires them.
- **One canonical verifier law.** Workbench, `/seal`, `/verify`, Offline Studio, the standalone Offline Verifier, and SDK projection consume the same completed canonical verification result. Resource failure remains an execution failure and can never be presented as an invalid-proof verdict.
- **Truthful typed projection.** Generic streaming-verifier bundle data is validated before it becomes `ReceizProofBundle`. The unsafe reseal assertion and the incompatible Workbench projection boundary are removed; a representation cannot be promoted into stronger proof truth by a TypeScript cast.
- **Canonical PBI authorship succession.** PBI signing appends authorship after the exact verified predecessor without transferring ownership. The descendant is admitted only after canonical verification, including Signature V4 payload binding and ownership-continuity checks.
- **Exact PBI descendant export.** Workbench exports the exact canonically verified PBI descendant. Optional badges or previews may render beside that proof object, but no signed-image representation may replace its bytes or inherit continuity from a different artifact basis.
- **Completed-proof Offline Studio QR.** Offline Studio projects the completed compact `?c=` proof URL as a clickable 92×92 QR after canonical success. It never substitutes the weaker `?ms=` historical lookup and never rewrites the recorded Moment source to embed a future-derived URL.
- **Direct `/v` proof classification.** A valid carried `?c=` bundle verifies as **Proof**. Historical coordinate lookup remains available for historical receipts, but cannot relabel a completed self-carrying proof URL.
- **Settled Profile with bounded media work.** The complete verified showcase remains held; the 24/18 monotonic presentation window and every admitted card shell remain unchanged. Grid cover loading is viewport-bounded beneath those shells, while one-column feature media stays eager, so secondary image requests no longer hold the cold navigation indicator open.

Native image, native video, uploaded video, and text-only Recorded Moments retain their exact proof identity; video playback remains an explicit Profile Composer/Profile Showcase presentation boundary beneath the proof object.
- **Native-image URL continuity restored.** Native-capture images reopen their exact payload from the self-contained carried proof URL after the composer-owned blob is released. The bounded-video held-source exception remains video-only, so this correction does not alter working video or image/audio global sync.
- **Showcase membership and owner signing access reconciled.** Identity Seal and Identity Record stay identity artifacts unless an actual showcase publication admits them; local session fallback no longer fabricates owner-only posts. A global post hands its authenticated owner profile to the already-open profile surface, so the existing signature control is present immediately instead of waiting for refresh to replace a logged-out/public viewer projection. Signing mechanics are unchanged.
- **Coordinated release identity.** Application, `@receiz/sdk`, `@receiz/mcp-server`, and `@receiz/ai-skills` align at `124.0.3` while `RECEIZ_RULESET_VERSION` and the V124 registry remain `124.0.0`.

## Why this matters

The failure was not cryptographic. It was architectural: browsers were asked to retain multiple full representations of the same large proof object, and an execution failure was allowed to resemble a proof verdict. V124.0.3 restores the correct jurisdiction. Source bytes decide the proof. Verification decides admission. Representations may help people play, scan, share, or inspect the admitted object, but they cannot delay, replace, or reinterpret it.

This correction also proves a broader release law. Compiler casts, UI labels, transport convenience, memory ownership, QR composition, and loading policy are not secondary details when they cross a proof boundary. Each must preserve the stronger source and name its exact uncertainty.
