# Receiz v121.0.0 Regression Lessons

## What Regressed

During alignment work, representation checks entered hot paths that already possessed stronger proof truth. That caused rejected composer payloads, missing media seals, page refreshes after publication, slow profile transitions, temporary wallet “Unavailable” states, local duplicate counts, and proof fields that appeared pending or disappeared even though the sealed object was correct.

The mistake was not the law. The mistake was applying the law backward: treating server, session, route, or projection confirmation as if it strengthened an already sealed proof object.

Fresh PWA publication exposed the same inversion at one final boundary: the composer created its coordinate locally, but the anchor route demanded a pre-existing DB ownership row before accepting download and custody controls. New-account timing could hide the bug by projecting the row first. The lawful rule is exact: accepted identity authorizes creation of a new unowned coordinate, an existing conflicting owner blocks it, and the later DB row distributes the result without becoming proof authority.

## Why It Regressed

The law was applied in the wrong direction: weaker server, session, route, and projection confirmations entered paths that already held stronger sealed or verified truth.

## What we learned

- Source-first does not mean server-last. Global indexing should begin immediately, but it must run beneath the settled proof surface.
- Stronger truth must merge monotonically. A smaller response is not permission to erase SHA-256, PBI, ownership, signature, or identity fields already verified.
- “Background” is a behavioral contract: it cannot submit a native form, navigate, reload, remount, or redefine first paint.
- Hydration is discovery of verified additions. Once verified and durable, repeating the same hydration is redundant work and a continuity regression.
- Caption-only content still has artifact bytes. Its deterministic sealed representation supplies a real SHA-256 even without uploaded media.
- Compatibility versioning must distinguish current coordinated identity from immutable historical proof law and stable protocol routes.

## Locked Rules

v121 adds release laws and contracts for source-before-representation publication, definite global append, no settled remount, media commitment preservation, strongest-field merge, durable cold heads, immediate Settlement projection, and full-session identity projection after proof acceptance.

The `@receiz/sdk` memory boundary remains **first admission only, then append forever**; refresh and hydration cannot substitute repeated admission.

## Contract Gates

The release lock, deterministic-surface suite, profile continuity contracts, Settlement and verification conformance, package contracts, and full release freeze block recurrence.
