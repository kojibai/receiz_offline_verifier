# Receiz v113.5.0 Regression Lessons

The public package surface is `@receiz/sdk`. Durable proof memory remains **first admission only, then append forever**.

## What Regressed

- Offline Record/Seal cannot depend on a live identity/session redirect to make a sealed proof object true.
- iOS Photos may normalize allowed JPEG/HEIC container details, so verification must bind a canonical basis and still fail closed outside that basis.
- A correct local verification verdict cannot wait for an optional append or be reversed by append failure.
- A retrying signed upload must retain the already prepared proof object.
- A lagging public/profile projection cannot replace stronger prepared, saved, or locally verified proof truth.
- A sports reward closeout under concurrency must settle once and remain settled.
- An inline native file label can collapse its visible drop surface even when its input remains technically operable; browser evidence must protect the complete offline proof surface.

## Why It Regressed

The edge cases came from weaker mechanics being allowed to approach an authority boundary: session/enrollment mechanics near offline sealing, container metadata rewrites near artifact identity, network append work near a local verdict, partial projections near saved proof truth, and retry/concurrency mechanics near settlement finality.

## Locked Rules

- A patch release version and a constitutional ruleset version are distinct facts. v113.5.0 publishes fixed packages while preserving the v113.0.0 ruleset and registry.
- Warning-free lint matters because unused bindings can hide real release regressions. Cleanup must remain behavior-neutral and separately reviewable.
- Release notes must be derived from the exact tag-to-head range, not from the nearby future branch.
- Generated SDK output, MCP dependencies, AI manifest distribution versions, runtime/service-worker labels, and release records must move together.
- Standalone proof instruments require fresh-browser visual evidence so a prior service-worker cache cannot masquerade as the current release candidate.

## Contract Gates

Tests and visual evidence must reject any return to network-first verification, payload substitution, Photos-carrier over-acceptance, proof-loss-on-retry, projection downgrade, duplicate settlement, changed first paint, or patch-version/ruleset conflation.

PR #223 remains v114 work and is not used to justify or describe v113.5.0 behavior.

## Release-Lock Requirement

`pnpm release:lock 113.5.0` must require this regression record. Network-first verification, Photos-carrier over-acceptance, payload substitution, prepared-proof loss, projection downgrade, duplicate settlement, first-paint instability, inline drop-surface collapse, and patch/ruleset conflation must remain independently reviewable boundaries.
