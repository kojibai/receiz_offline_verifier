# Receiz v110–v118: The Proof-Native System Arc

Receiz v118.0.0 is the major-release closure of the system built from v110
through v118: exact files become proof objects; admitted identity determines
who may act; ownership and settlement append without rewriting history; known
verified truth paints before weaker discovery; and every public, offline, SDK,
MCP, and AI surface remains beneath the enclosing artifact.

The exact 452-commit implementation ledger is preserved in the
[complete commit history](./v118.0.0-commit-history.md). This document explains
the architectural arc those commits produced.

## v110 — Unified admission and recovery

V110 made one enclosing-artifact-first admission boundary span canonical
identity, bearer recovery, verified legacy reads, foreign ownership, and
invalid inputs. Recovery became a deterministic read-only plan followed by a
separate, capability-bound atomic commit. Plans, explanations, receipts,
sessions, databases, MCP, and AI could no longer manufacture authority.

## v111 — Authority derived from exact artifact evidence

V111 closed the remaining structural-object gap. Recovery-authoritative values
had to be derived from canonically reverified bytes; canonical identity needed
a live domain-separated challenge; and recovery plans bound the complete
authority basis. MCP separated stable plan identity from unique execution
attempt identity so a prior confirmation could not authorize a later attempt.

## v112 — The executable authority hierarchy

V112 turned the proof hierarchy into an explicit transition system: verify
exact bytes, admit membership, establish actor and predecessor evidence, plan a
registered transition, authorize that exact plan, stage neutral immutable
candidate bytes, independently reverify at commit, and atomically advance one
named domain. The recursively frozen registry, browser admission ledger,
Identity Seal capability signing, namespace preservation, and non-authoritative
receipt boundary became public SDK contracts.

## v113 — Production global reconciliation beneath artifact truth

V113 introduced the named `receiz.com/global/v1` coordination domain. Private
immutable staging, expected-head acceptance, idempotency, effects, and outbox
coordination made offline-to-global reconciliation operational without turning
“global” into authority above the sealed artifact. SDK, MCP, and AI converged
on five transition tools plus four reconciliation tools—one nine-tool current
inventory with the five-tool v112 inventory retained only as history.

## v114 — Recursive composite proof objects at product scale

V114 made Profile itself a stable sealed composite proof object and Economy a
recursive proof object over admitted Profile heads. Market became a
digest-bound projection beneath Economy. Bounded deltas, Merkle frontier state,
sparse Fibonacci checkpoints, immutable segments, carried history, and sealed
first-paint windows allowed proof state to extend to million-object scale
without turning database rows, indexes, sessions, or projections into truth.

This release also settled the visible law: a held verified Profile or Economy
head paints first; hide/show, ownership, order, signed downloads, and recovery
append exact successors; partial or stale discovery cannot erase a settled
surface.

## v115 — Native provenance and offline PBI authorship

V115 added `receiz.native_capture.v1` and
`receiz.pbi.proof-object-authorship.v1` as verified appends beneath the same
enclosing artifact. Native Capture binds exact camera-ceremony bytes without
claiming sensor certification. PBI authorship binds predecessor digest, proof
head, order, identity, credential, coordinates, and Kai/Chronos event without
changing ownership or media. Local settlement completes first; optional global
publication drains through a durable outbox. The standalone verifier remained
the one canonical offline verifier.

## v116 — Direct creation, entitlement, and continuity

V116 promoted the proven proof system into a direct product: a new account’s
first useful act became creating a verified Original. Free creation, identity,
proof, ownership, verification, and sharing remained the core; Creator, Live
Twin AI, Business execution, and non-expiring credit reconciliation gained
precise entitlement and dispute continuity. Accepted PBI identity and known
proof truth remained visible across return, refresh, and payment-state change.

## v117 — Whole-product continuity and public proof moments

V117 closed the application surface. Contacts, Profile, Wallet, Sports, Market,
and installed-PWA paths preserve stronger carried truth through hydration,
deployment, partial payloads, session publication, and cache rotation. Sports
Arena retained its complete interaction and proof-save experience while moving
below the 500,000-byte source gate.

Public proof became ready to travel. `/t/` gained the light institutional
transaction image with masked identities and non-overlapping settlement facts.
Adaptable `/v/` “This happened” moments covered transactions and other proof
objects. Share text became ready-to-send for Twitter, iMessage, and native
sharing. Metadata and image work moved outside deterministic first paint.

Conformance became harder to accidentally short-circuit: the release freeze
continues after unavailable isolated integrations, aggregates genuine failures,
and runs settlement, issuance, verification, sports, signal, governance,
performance, and product-law contracts.

## v118 — One exact release identity and a file that proves its transaction

V118 corrects the release process itself. The app, SDK, MCP server,
constitutional verifier, AI package, all 26 AI manifests, current registry,
ruleset, SDK/MCP range, 16-row operation matrix, matrix digest, and nine-tool
MCP inventory now resolve to one coordinated identity. Publication and packing
run the gate. Mutation tests prove version, ruleset, registry, range, matrix,
and tool drift are rejected. A clean consumer proves equality from packed
tarballs without workspace source.

The `/v/` transaction download now carries the exact existing
`receiz.wallet_ledger_receipt` proof object inside the image artifact. The image
is a verified append beneath that transaction—not a replacement transaction
and not a reseal of it. It includes a QR code back to the canonical `/v/`
public proof surface. The unchanged offline verifier accepts the downloaded
image and rejects a tampered embedded transaction with an artifact-binding
failure.

Wallet settlement evidence is now directly reachable from Value source,
Settlement math, Transfer runbook, and Ledger contract. Proof-native keeps its
settled appearance and opens a tasteful conformance popover whose pill links to
Settlement Conformance. Logged-out `/wallet` truth is explicitly `$0`; it no
longer presents absence of an authenticated settlement account as
“Unavailable.” Signed-in settlement truth and the visible settlement surface
remain unchanged.

## The resulting system

Receiz at v118 is one proof-native artifact system:

1. exact enclosing artifact truth is verified locally
2. identity, authorship, ownership, settlement, and provenance append under
   explicit authority
3. durable local truth paints before weaker discovery
4. Profile, Economy, Market, Wallet, Sports, Contacts, and public witness
   surfaces project beneath that truth
5. files remain independently verifiable offline
6. SDK, MCP, AI, compiler, verifier, and packages cannot claim different
   current contracts

The 15-task orchestration program is not part of this shipped arc. It is
preserved without loss in the [v119 implementation plan](./v119.0.0-planning.md).
