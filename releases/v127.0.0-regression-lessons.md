# Receiz v127.0.0 Regression Lessons

## What Regressed

The developer distribution did not expose the complete offline sealing runtime already implemented in Studio. SDK HTTP creation and unresolved MCP sealer hooks could be mistaken for executable offline support.

The post-v126 history also records continuity regressions: stale sessions contested admitted identity; hydration disturbed ready Showcase media; hidden/unhidden publication diverged; transport outages blocked held-proof recovery; and Mind's native cold opening displayed empty memory while retained history existed. Earlier installed local-model references still named the removed application path. These were failures at concrete source, projection and distribution boundaries.

## Why It Regressed

Capability descriptions exceeded the packaged execution path. A tool name, skill instruction or adapter interface did not supply signer custody, proof resources or an executable local sealer.

Across continuity repairs, weaker representations were allowed to delay stronger held truth. Background discovery, partial history pages, app-path references and session responses cannot decide whether an admitted proof object exists. Eventual recovery did not repair an incorrect first paint.

Mind's superseded native build passed notarization but failed visible cold-open evidence. It was withheld and replaced with the qualified build 2026092205. This establishes the exact lesson: signing and package acceptance prove their own boundaries; they cannot certify memory continuity or the visible product.

## Locked Rules

- Ship the canonical implementation and verify installed-package execution after restart with networking disabled. Enrollment remains explicit and separate from offline operation.
- Package public roots and exact proof resources; retain device private keys locally. No root injection, new authority or self-hashed payload can replace enclosing proof verification.
- Project retained enclosing proof heads before background history reads. Request verified additions after held checkpoints; never page already-admitted truth back into existence.
- Preserve exact source, signer custody, identity scope and existing user history through upgrades. Repair bundled-model references without replacing unrelated custom models.
- Keep generated answers grounded in current evidence and isolated by identity. Conversation continuity does not turn generated prose into proof. Do not advertise completed-response sealing while that work remains deferred.
- Freeze and qualify the exact artifact distributed. Verify complete public bytes against its digest. Preserve failed candidate evidence and identify the final section that supersedes it.
- Treat screenshots, recordings and DOM evidence that contradict a claimed pass as failures. Passing tests, notarization or eventual recovery cannot override them.

## Contract Gates

V127 outage qualification exposed concrete retention failures. Complete profile snapshots exceeded WebStorage capacity; lossless encoding now retains the entire source under codec-versioned keys. A null equality branch discarded a held profile seed. Optional service-worker discovery could stall installation. Internal custom-domain warming mistook a dotted hostname for an asset extension, and public media warming used an accepted image format under a different `Accept` header than the browser. The repairs preserve exact source, canonical route admission, cache variation boundaries and explicit privacy revocation.

Repeated outage reloads then exposed the source of media loss: a storage transport failure became `null`, the artifact route reported 404, the image proxy preserved that status, and the worker correctly revoked the held media. The repair belongs at storage classification. Transport unavailability now remains 503 through the material routes and signed-object URL issuance; genuine object absence and invalid proof retain their existing outcomes. The worker still revokes explicit access failures and removes all variants for the exact URL so another cache cannot resurrect revoked media. A passing first reload alone is insufficient evidence: verify repeated reloads, exact held document and media bytes, and settled visible identity.

Live Twin stage qualification exposed a separate retention gap. Commit `bd5afb8517` (v41.0.4) introduced a `no-store` exception for the already-public `receiz-world-media` bucket. That is the historical origin of a retained policy, not an older application version running inside v127. `storeWorldAvatarAssets` already publishes avatar versions at timestamp-and-content-hash paths, separately from owner-only World source and performance objects. V127 applies the existing public-media retention policy to those public avatar bytes without changing any access rule or adding an authority layer.

Three loads stage textures through detached images, so scanning only `document.images` missed textures loaded before service-worker activation. The existing media warmer now also discovers completed same-origin image resource requests on its existing supported paths. These are warm hints only: the worker still requires its existing public-response admission, preserves request variation boundaries, and enforces genuine revocation. Private source/performance buckets remain owner-only. Final qualification must include the full stage in the screenshot and compare retained texture bytes across repeated source-outage reloads; hero and Showcase media alone cannot certify stage continuity.

The [final profile evidence](evidence/v127.0.0/profile-source-outage.md) preserves both full outage screenshots and the earlier failed capture. Exact document and 12 held media resources survived both reloads. A separate healthy-source control reproduced the blank stage seen before WebGL initialization; final stage screenshots require observed draws. This proves retained texture and resulting stage rendering, not immediate stage first paint. Profile first-paint measurements remain separate, and no renderer behavior was changed.

Offline qualification, exact generated runtime/resource checks, SDK custody tests, MCP runtime tests, installed-package execution, coordinated package tests, release-freeze and the frozen Offline Studio contract protect the new developer distribution.

Account-entry, source-authority, deterministic first-paint, visual-evidence and primitive-binding contracts protect the existing primitives. Mind's native bootstrap, retained-history, model-upgrade, conversation-scope, safe Markdown and exact distribution checks have their separate release ledger. Their historical results must not be reported as a fresh v127 main-release pass.
