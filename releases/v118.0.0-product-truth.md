# Receiz v118.0.0 Product Truth

Public developer surface: `@receiz/sdk` v118.0.0. Durable proof memory remains
**first admission only, then append forever**.

## Frozen Primitives

Receiz is a proof-native artifact system. The `/v/` transaction download is a
proof object because it preserves deterministic transaction identity, carries
the exact verifiable transaction payload, binds that payload into a verified
enclosing image artifact, survives outside application state, and can be
inspected by the offline verifier.

The image is an append beneath the transaction proof object. Its visual moment,
QR, artifact anchor, Signature V4, and Groth16 material do not replace, rewrite,
or independently authorize the transaction. Verification starts with the
stronger enclosing artifact and then projects the embedded transaction.

Wallet is a settlement primitive. `$0` is the truthful logged-out display
state; authenticated account settlement remains proof-native state and is not
renamed into generic balance authority. Settlement Conformance is evidence
beneath that primitive, not a new settlement authority.

## Frozen Invariants

1. sealed artifact and embedded proof truth
2. deterministic proof-object identity and verified history
3. durable local truth and verified register append
4. authenticated snapshot and server append
5. database, session, and UI projection

No v118 change reverses this order. Metadata, OpenGraph generation, QR
rendering, sharing, package projection, and conformance display remain beneath
known proof truth and outside deterministic first paint.

## Release Gates

The SDK is canonical for current release identity and application operation
matrix. MCP imports those values directly and exposes them as a non-authoritative
projection. AI manifests embed the exact matrix for deterministic instruction
projection. An independent validator recomputes the matrix digest and rejects
any mismatched version, ruleset, registry, range, matrix row, or MCP tool.

Packed-package qualification repeats the comparison from tarballs in a clean
consumer. Source alignment alone is insufficient.

## Historical continuity

V110–v117 registries, exact matrices, artifacts, and compatibility readers
remain immutable historical surfaces. V118 appends its current identity; it
does not rewrite prior release truth. Existing verified files remain eligible
for current verification under their historical contract.

## Residual Risks

V118 does not claim that MCP or AI is proof authority, that a QR proves a
transaction, that logged-out `$0` is an authenticated settlement account, or
that the v119 orchestration plan shipped. It also does not claim external
publication, signing, deployment, or production smoke.
