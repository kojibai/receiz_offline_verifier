# Receiz v121.0.0 — Source-First Continuity

Release date: 2026-08-19

v121 locks the final continuity boundary between sealed proof-object authority and its fast global representations. Sealed proof objects, verified identity, and lawful Settlement/Reserve state remain the source. Server, database, session, cache, and public indexes distribute, restore, and project that truth at full speed without becoming authority.

## What changed

- Profile Composer seals caption, long-form, image, video, audio, and other supported media through the established proof path, preserves the real media SHA-256, and publishes verified public objects to the global composite head.
- A successful seal projects into the settled profile immediately without a page reload. Global indexing continues beneath that settled proof and retries durably when required.
- Weaker partial projections can no longer erase stronger known proof fields such as media SHA-256, PBI, signature state, or stable proof identity.
- Caption-only and long-form proof objects carry deterministic artifact SHA-256 commitments even when no uploaded media exists, and the live player and artifact manifests project those commitments.
- Verified showcase hydration becomes durable cold-load truth. Later lawful proof objects append; hiding changes visibility without rewriting history.
- Accepted Receiz identity proof projects the complete account immediately. Import, bind, recovery, and global-sync work cannot leave the user half logged in.
- A freshly signed-in PWA account may publish custody and download policy for its new locally sealed coordinate immediately; absence of a servant DB ownership row cannot deny creation, while an existing conflicting owner still blocks it.
- Known verified Settlement and Reserve state paints immediately, including Glyph-entitled accounts; newer lawful ledger additions reconcile behind it.
- The compact mobile bottom bar remains right-aligned and only as wide as its controls.

## Authority boundary

The sealed proof object is authority. A composite head is a proof object that carries append-only public state. The server and database may locate, index, distribute, backfill, and restore exact verified objects. They do not decide whether those objects are true and never block deterministic first paint.

## Compatibility

All previously sealed proof objects remain byte-exact and verifiable under their original law. Existing v120 HTTP protocol routes remain supported; v121 coordinates the current package/ruleset identity without renaming compatible protocol endpoints. Mutable usernames remain profile labels bound to stable Receiz ID identity.

## Qualification

The v121 release lock binds package versions, registry digest, application-operation matrix digest, AI manifests, documentation, visible release surfaces, service worker, and release-freeze membership. Full qualification is recorded independently from publication, deployment, signed attestation, and production smoke evidence.

Durable proof memory remains **first admission only, then append forever** across `@receiz/sdk`, the application, and every projection.
