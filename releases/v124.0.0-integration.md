# Receiz v124.0.0 Integration — Reality Becomes Infrastructure

**The Production Runtime for Verified Civilization.** Integrations begin with an independently verified sealed proof object and preserve exact authenticated heads through every remote coordination step.

## Universal flow

1. Verify the complete enclosing proof object locally with the existing Receiz verifier.
2. Derive live `{ pulse, uPulse }` from pulses since genesis. Do not initialize from a signed-snapshot default, override, or process uptime.
3. Create a canonical whole-pulse proof-authority challenge for the declared `applicationId`, artifact digest, scopes, consent digest, nonce, and bounded TTL.
4. Open or refresh short-lived authority only after existing application/audience admission and artifact/consent verification succeed.
5. Qualify every production dependency as operational with evidence.
6. Stage the complete canonical plan under an idempotency key, execute it once, and resolve ambiguity before retry.
7. Admit replay, checkpoints, additions, and namespace metadata only after full proof/head validation.
8. Hydrate private additions only after access filtering.
9. Execute multi-domain world and inventory/material effects atomically.
10. Resolve transfer recipients through the rate-limited, non-enumerable resolver and bind the returned coordinate into the transfer proof flow.

## Compatibility rules

V123 whole-pulse fields and stable v122/v123 protocol names remain unchanged. Micro-pulse precision uses newly versioned fields. Existing application/principal admission remains in force; no integration should register a duplicate identity or create a consumer-specific admission path.

Runtime results are coordination evidence, not object authority. Durable proof memory remains first admission only, then append forever.
