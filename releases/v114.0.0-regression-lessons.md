# Receiz v114.0.0 Regression Lessons

The public package surface is `@receiz/sdk`. Durable proof memory remains **first admission only, then append forever**.

## The Original Failure

The composer reached anchor and render, then reported `Could not render the anchored receiz artifact.` The immediate symptom was not simply database memory. It exposed a deeper architecture that repeatedly reconstructed a large profile showcase through weaker storage/projection paths even though the user already held the proof objects needed for the next state.

The correction is not a larger database query. The correction is to append the new proof object to the already admitted profile proof object and append that exact resulting profile proof object to the economy.

## What Regressed During Closure

- SDK source exported persistent showcase state while the committed distribution omitted it.
- Verification caches retained unbounded certificate/key material.
- Identity export and restore paths did not always admit usable Identity Record custody.
- Composer publication could report success without sealing the profile/economy append.
- Existing profiles could create an empty genesis instead of migrating complete history.
- Public projections could remain unsigned, hidden, reordered, stale, or bound to an expiring URL after proof mutations.
- Market could retain the oldest profile head.
- Economy recovery could substitute historical members without membership proof.
- Economy siblings could overwrite one another, and first bootstrap could fail every CAS retry.
- Economy append failure could disappear without durable retry.
- Visibility could update the database while leaving the bounded proof head stale.
- Logout could clear custody and still lose a race to a stale async finalizer.

## Why These Regressions Were Possible

The code had implemented major proof primitives, but several production call sites still treated them as optional enrichment. That allowed UI success, database success, or projection success to stand in for complete proof settlement.

The recurring category was a truth-order inversion:

- projection near proof authority
- session context near Identity Record authority
- a synthetic predecessor near the actual active pointer
- count/delta checks near historical membership proof
- browser cache memory near bounded verified custody
- test fixture format near production sealed bytes

Each weaker mechanic is useful. None may decide the stronger truth boundary.

## Locked Lessons

- Implemented proof machinery must be wired through production call sites; existence in SDK/tests is not settlement.
- A proof append that is required by law cannot be an optional callback with no production consumer.
- Every accepted composite state must itself be sealed.
- Exact stable identity and verified descent choose the newest profile state, not array position.
- First CAS bootstrap is a transition from `null`; later CAS is a transition from the exact active digest.
- Failed global/economy work must remain durably retryable beneath local sealed settlement.
- Existing history must be migrated before a new head can claim completeness.
- Visibility is a proof mutation, not only a database/display toggle.
- Contradictory pending state must quarantine stale local authority without delaying valid settled first paint.
- Identity custody needs both explicit clearing and cancellation of stale asynchronous admissions.
- Stable public actions must persist stable routes or storage references, not expiring transport tokens.
- Source and committed SDK distribution must expose the same law surface.
- Scale claims must distinguish bounded foreground append from linear archive maintenance.
- Visual evidence scopes its claim. A settled shell screenshot does not prove loaded media or the full composer ritual.

## No Regression by Addition

V114 adds new profile/economy carriers, registry laws, custody, transition, migration, and projection mechanics. It does not rewrite old sealed proof objects, remove v113 coordination behavior, or replace first paint with background discovery.

The database remains subordinate. IndexedDB remains subordinate. Merkle and Fibonacci structures remain subordinate. The release does not trade product truth for a new generic authority layer.

## Future Contract

Any future change to posting, visibility, profile routes, Market, identity restore/logout, economy reconciliation, SDK distribution, or migration must run the exact contracts protecting:

- sealed successor identity
- admitted-child and carried-history evidence
- deterministic first paint
- migration completeness
- economy CAS/bootstrap/sibling convergence
- durable retry
- newest verified descendant
- visibility quarantine and successor settlement
- custody generation cancellation
- stable signed-download projection
- bounded verifier memory

## Release-Lock Requirement

This record is mandatory release evidence. A later release cannot describe the
historical composer failure as contradicted without a fresh authenticated
end-to-end capture, cannot turn projection or database success into proof
settlement, and cannot omit the standalone/upstream history distinction.
