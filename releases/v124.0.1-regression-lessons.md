# Receiz v124.0.1 Regression Lessons — Reality Becomes Infrastructure

**The Production Runtime for Verified Civilization.** These locks prevent tooling projections from outranking the sealed proof object.

Durable proof memory remains first admission only, then append forever. `@receiz/sdk`, MCP, AI, server, database, and session state may project or extend verified truth but cannot replace it.

## What Regressed

- V124 SDK operations existed without direct MCP adapters in the published `124.0.0` package.
- Developer OIDC selectors were expanded, but older agent-token and MCP-login fallback lists could still omit lawful scopes.
- Special MCP inventories were represented to AI and Academy while the complete current runtime inventory was not locked as one exact set.
- A valid saved receipt URL could be rejected when its weaker database/anchor projection was unavailable.

## Why It Regressed

Capability truth was repeated in multiple partial lists. Tests proved individual groups but did not prove that every emitter and projection equaled the complete canonical inventories. Receipt routing also allowed the absence of a weaker anchor projection to outrank a valid coordinate proof.

## Locked Rules

- One universal OIDC scope catalog governs developer creation, discovery, token fallback, and parity contracts.
- The complete current MCP runtime inventory is a machine-bound contract; special V122/V123/V124 groups are subsets, not substitutes.
- MCP descriptions and results state that MCP is not authority.
- Replay candidate bytes must be sealed through the canonical proof-object path before restore.
- Valid portable receipt coordinates survive unavailable database/anchor projections; altered coordinates do not.
- `.v124` machine identifiers remain versioned forever because they bind immutable schema/law identity.

## Contract Gates

- OIDC catalog rendering, validation, discovery, agent-token fallback, and MCP-login scope equality
- exact full-current MCP inventory parity across runtime, AI index/manifests, and Academy
- exact 22-tool V124 SDK/MCP mapping, scope, custody, reference, and response-redaction contracts
- database-independent receipt positive and altered-coordinate negative tests
- coordinated `124.0.1` package identity with immutable `124.0.0` ruleset/registry evidence

## Standalone Lock

The standalone regression guard validates patch identity separately from constitutional identity. A future patch cannot silently demand a same-numbered registry file, rewrite the frozen V124 registry, or imply that a package version changes proof law. Exact-file verification remains the primitive; visible labels and service-worker epochs remain subordinate release surfaces.
