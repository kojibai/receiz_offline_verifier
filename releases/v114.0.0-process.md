# Receiz v114.0.0 Release Process

The public package surface is `@receiz/sdk`. Durable proof memory remains **first admission only, then append forever**.

## Goal

Replace foreground profile reconstruction with an exact sealed composite append, then apply the same recursive law to the economy without changing existing proof objects, visible posting behavior, deterministic first paint, or the v113 global-coordination rail.

The functional release range is `v113.5.0..ddd66cd59`. Release-only documentation follows that fixed-code head. Package/runtime promotion, generated distribution refresh, attestation, publication, deployment, and migration remain explicit later actions.

## Method

1. Define the profile showcase as a stable sealed proof object rather than a page-local array.
2. Freeze proof identity, carried history, transition authority, and accepted-child evidence in SDK contracts.
3. Introduce bounded state: one direct delta, compact Merkle frontier, sparse Fibonacci checkpoints, immutable segments, and a sealed first-paint window.
4. Persist only verified edge custody and require re-admission before use.
5. Seal composer Originals as admitted profile children and construct the next exact showcase successor.
6. Migrate complete legacy history deterministically before allowing an existing profile to enter the new head chain.
7. Reuse the recursive composite kernel for `economy-showcase:receiz.com`.
8. Bind Market projection to exact admitted economy state.
9. Add compare-and-advance, durable retry, sibling preservation, membership proof, and newest-descendant selection.
10. Close identity custody, public projection, signed-download, pagination, ordering, and visibility-transition gaps found by review.
11. Prove bounded behavior at 100,000 and 1,000,000 profile children and 1,000,000 economy profiles.
12. Run focused contracts before wider release-law gates and production build.
13. Freeze exact evidence in the release book before version promotion or deployment.

## What Worked

- Starting from the proof object as authority exposed the original scaling defect: complete feed reconstruction was unnecessary rediscovery of already known truth.
- One recursive composite kernel made profile and economy behavior structurally identical instead of creating a second authority model.
- Exact runtime custody prevented serializable handoffs from impersonating admitted artifacts.
- Separate bounded append and archive-compaction contracts distinguished foreground scale from linear maintenance work.
- Review findings were evaluated against repo law and converted into executable failure contracts rather than accepted as generic software advice.
- The active-head CAS tests exposed both sibling replacement and the first-bootstrap `null` mismatch.
- Visibility quarantine preserved deterministic truth ordering: a known-stale head is not allowed to overwrite the correct server projection while the sealed successor is pending.
- Moving visibility settlement behind a dynamic import preserved the existing profile source-size/performance contract.

## What Did Not Work

- The initial production closure left some proof-native functions present but unwired. Test-only surfaces are not production settlement.
- Optional custody and reconciliation parameters allowed successful UI publication to omit profile/economy proof settlement.
- Empty-genesis fallback for an existing profile would have made earlier Originals disappear.
- First-write economy CAS initially compared `null` storage against a non-null synthetic predecessor and rejected every bootstrap attempt.
- A direct visibility projection update did not change the held bounded head, allowing stale first paint to resurrect hidden Originals.
- Clearing custody at logout was insufficient while an older async finalizer could later re-admit the same key material.
- Inlining the complete visibility transition into `ProfileClient.tsx` crossed the Babel deoptimization threshold. Extracting the proof operation restored the performance contract.
- JSON-only child fixtures hid the production PNG child payload format.
- First-page-only hidden Original recovery failed beyond the server page-size clamp.

## Evidence Discipline

Passing tests do not overrule contradictory visual evidence. The repository’s Market and Original captures support those public proof surfaces. The profile capture supports the settled identity/shell only. The historical composer error screenshot is not marked contradicted until a new authenticated end-to-end capture proves the complete ritual.

Likewise, a previous uninterrupted release-freeze run is historical evidence. The checklist does not mark the post-documentation umbrella gate complete until it is rerun from the final tree.

## Promotion Sequence

1. Promote app, SDK, MCP, verifier, AI-skills manifests, generated distribution, runtime identity, and service-worker identity to `114.0.0` in one coordinated change.
2. Switch the current ruleset/registry/matrix compatibility identity to the frozen v114 artifacts without mutating prior registries.
3. Run packed-package qualification and full `pnpm test:release-freeze`.
4. Capture the authenticated composer, immediate profile, economy/Market continuity, visibility, reconnect, and merge evidence.
5. Generate and verify the signed release attestation using configured approval and signing values.
6. Commit/tag the exact release tree.
7. Publish packages and deploy only with explicit authorization.
8. Run production smoke verification.
9. Execute production migration only with separate explicit authorization; preserve dry-run and fail-closed exception reporting.

## Practical Rule

Release mechanics report the proof-native implementation; they do not become its authority. A version label, Git tag, deployment, database migration, or attestation cannot replace the sealed profile/economy proof objects described by this release.
