# Receiz v113.5.0

Release date: 2026-07-26

Receiz v113.5.0 is the clean stabilization release for every fix merged to `main` after v113.0.0 and before the separate v114 development line.

Release range: `v113.0.0` (`32da10fed284237d418c860c65a595a442bf6c07`) through fixed-code head `0c68fe4aa1bdd04e1f8161642778ad427dccb9e9`, 54 commits and 135 changed files before the release-only version and evidence commit.

The coordinated public distribution is versioned together:

- Receiz app: `113.5.0`
- `@receiz/sdk`: `113.5.0`
- `@receiz/mcp-server`: `113.5.0`
- `@receiz/ai-skills`: `113.5.0`
- constitutional verifier package: `113.5.0`

The frozen v113 ruleset, constitution registry, artifact-law version, application operation matrix, compiler target, and SDK/MCP compatibility interval remain v113.0.0 / `>=113.0.0 <114.0.0`. This patch release does not invent a v113.5 authority layer and does not absorb v114 work.

Durable proof memory remains **first admission only, then append forever**.

## What Changed

### Offline Record and Seal now preserves the exact proof object

- Offline Studio can Record and Seal without requiring a Receiz identity while still using canonical Signature V4 proof mechanics.
- Device signing moved to local-first enrollment with canonical server enrollment, fixed certificate expiry, and optional authenticated ownership.
- Record/Seal no longer redirects through sign-in or leaves the surface half-provisioned.
- Trailer-sealed image bytes, source format, download MIME, and exact-file download/share behavior are preserved.
- PNG bases exclude mutable provenance and anchor chunks before sealing.
- The standalone offline proof instruments remain exact and independently usable.

Why: an offline proof object must remain the same sealed artifact across save, share, camera-roll handling, download, and later verification. Identity/session mechanics cannot outrank or rewrite the artifact.

### JPEG and HEIC proof carriers survive real iOS Photos transformations

- JPEG XMP-normalized artifact binding was added and frozen by contract.
- The JPEG carrier advanced through fail-closed IFD1 v3, iOS Photos normalization, MakerNote v4, v5 basis handling, and v6 rational canonicalization.
- Native HEIC proof objects gained file detection, a canonical UUID proof channel, Record/Seal creation, camera-roll-safe saving, offline verification, and UI projection.
- iPhone PWA save behavior now uses the exact-file download surface and native file sharing where available.
- Simulated iOS Photos transformations and first-save evidence are locked into regression coverage.

Why: Photos applications may rewrite container metadata without changing the human-visible media. Receiz must recompute the permitted canonical basis, reject unsupported mutations, and preserve the proof object’s deterministic identity without relying on a server.

### Verify is proof-native and useful in airplane mode

- `/verify` now verifies local proof objects before network, session, append, or server work.
- The installed PWA and standalone verifiers preserve offline verification for JPEG, HEIC, and existing sealed proof carriers.
- Optional append work is isolated in a durable outbox and cannot change the local verification verdict.
- The service worker preserves exact offline proof instruments and avoids fake loading or network-first rediscovery of known proof truth.

Why: offline verification is the primitive, not a fallback. A valid sealed proof object must verify by recomputation from its own bytes; later appends may enrich history only after the verdict is settled.

### Signed upload and public-proof continuity edge cases were closed

- Interrupted signed uploads can retry without losing the prepared proof object.
- Lagging public projections cannot overwrite stronger prepared or locally held proof truth.
- Profile visibility queries are bounded, saved proofs are defended, and global publish/sync contracts protect the completed proof object.
- PBI authorship no longer depends on a generic anchor-verification prerequisite.

Why: server rows, partial public projections, and retry state are weaker than the sealed or prepared proof object. They may index or append beneath it but cannot erase or downgrade it.

### Sports reward closeout is atomic under pressure

- Sports reward closeout gained a durable queue, explicit atomic closeout behavior, backpressure handling, worker routing, and focused tests.
- Main Event / arena settlement cannot double-close or silently lose reward completion when concurrent work or retries occur.
- Pitch Command’s completed archive window and packaged day-proof evidence were brought current.

Why: reward closeout is a settlement primitive. A completed reward must have one durable terminal state; retries and worker pressure cannot manufacture a second settlement or reopen a settled one.

### Deterministic first paint and release quality were tightened

- First-paint typography is locked across Safari and installed PWAs.
- Service-worker and offline-studio release identities advance together to invalidate old runtime shells without changing settled product logic.
- The standalone Offline Studio file targets now render as full-width drop surfaces instead of collapsing as inline labels; a frozen contract prevents recurrence.
- Lint now completes with zero warnings. Cleanup was limited to unused imports, unused dead helpers, an unused function parameter, and an underscore convention for intentionally discarded test bindings.

Why: a clean release must identify the exact shipped runtime, preserve deterministic first paint, and contain no warning noise that could hide a later regression.

## SDK, MCP, and AI Skills

The v113.5.0 SDK contains the offline proof-carrier, verification, continuity, retry, and settlement fixes shipped in the app. The SDK runtime constant and package manifest are coordinated at `113.5.0`.

The v113.5.0 MCP server remains bound to the existing nine v113 artifact/reconciliation tools. No tool is added, removed, or promoted above sealed artifact truth in this patch.

The v113.5.0 AI-skills distribution carries the updated v113 operating contracts at package/manifest version `113.5.0` while continuing to require the frozen v113 ruleset, registry digest, operation-matrix digest, and SDK/MCP compatibility range.

## What Is Not In This Release

PR [#223](https://github.com/kojibai/receiz/pull/223), `kojib/profile-showcase-proof-composites`, is the separate v114.0.0 development line. Its profile-showcase proof-composite architecture is not part of the `v113.0.0..main` stabilization range and is not described as shipped in v113.5.0.
