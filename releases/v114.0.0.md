# Receiz v114.0.0

Release-candidate date: 2026-07-27

Receiz v114.0.0 makes the profile showcase itself a sealed composite proof object and applies the same recursive law to the global economy showcase. A post no longer becomes globally complete because a database row or display projection exists. The accepted profile successor is the authority; the economy appends that exact admitted profile proof object; Market is a digest-bound projection beneath the economy proof.

Release range: `v113.5.0` (`8f081b1eeee10c2cb9445686116d5120828cfe1a`) through fixed-code head `ddd66cd59`, 94 commits and 341 changed files before release-only documentation.

Durable proof memory remains **first admission only, then append forever**.

## The Architectural Correction

The profile showcase has stable proof identity `profile-showcase:<Receiz ID>`. Every accepted state is itself a sealed successor proof object. The successor carries one bounded direct delta, the exact predecessor commitment, compact Merkle frontier state, sparse Fibonacci checkpoints, immutable segment references, a carried history head, and a sealed first-paint window.

The economy uses the same law one level higher under stable proof identity `economy-showcase:receiz.com`. It appends exact admitted profile showcase heads, not re-discovered profile arrays. Each economy successor binds the admitted profile artifact digest, version, carried-history head, and admission-evidence root. Market derives from that verified economy state.

This is the same recursive operation from one Original to one profile, from profiles to the economy, and from the economy to deterministic public projection:

1. verify the stronger enclosing proof object
2. admit its exact identity and carried history
3. append one bounded proof delta
4. seal the resulting composite as the next proof object
5. project beneath the sealed result
6. reconcile verified additions without re-finding known truth

Merkle roots, Fibonacci checkpoints, IndexedDB indexes, database rows, session state, published manifests, and Market snapshots remain mechanics or projections. None becomes authority above the sealed proof object.

## Posting and Composer Settlement

- The composer preserves the existing anchor, render, seal, upload, and publication ritual.
- A successfully sealed Original is admitted as an exact profile child before the profile successor is constructed.
- Identity Record custody supplies the exact actor authority required to seal the profile transition.
- Identity Record exports forward their passphrase into custody instead of silently storing an unusable record.
- Receiz Key restores admit the accepted Identity Record into the same custody used by newly created identities.
- Composer publication no longer silently skips a showcase append when custody is unavailable. It reopens persisted custody or reports an explicit proof-settlement failure.
- A new browser must migrate the complete admitted legacy showcase before it may append. It cannot manufacture an empty genesis that erases earlier Originals.
- Once the profile successor is admitted, it is durably queued into the browser economy. Transient economy failure is retained for retry instead of being discarded.

Local sealed settlement remains true when a weaker projection or global synchronization path is unavailable. The weaker failure cannot revoke the accepted proof object.

## Deterministic First Paint

- A verified held profile head paints before network discovery, database reconstruction, session lookup, or global synchronization.
- A verified held economy head paints its digest-bound Market projection before weaker refresh work.
- The bounded first-paint window reuses already admitted proof truth; pages do not rescan complete profile history to recover facts they already hold.
- Missing edge custody does not blank stronger server-rendered public truth.
- A held bounded head cannot replace the route with an incomplete or unverified child projection.
- Visibility transitions quarantine a known-stale bounded predecessor before the database write. First paint may not resurrect a hidden Original while the exact sealed successor is still being produced.
- The quarantine is released only after the visibility successor is sealed, admitted, published, and enqueued.

No first-paint path waits for economy retries, migration, profile reconstruction, or session rediscovery.

## Scale and Storage

Foreground profile and economy appends are bounded by the compact head and the one new delta, not by the total number of prior posts or users.

The executable scale contracts prove:

- a bounded append after 100,000 profile children
- a bounded append after 1,000,000 profile children
- a bounded economy append after 1,000,000 admitted profile heads
- one direct delta operation, bounded Merkle carry work, sparse Fibonacci checkpoint work, one coordination write, and one derivative effect
- no artifact bytes, private URLs, credentials, or full historical arrays in scale metrics

The physical archive-compaction soak remains a separate linear maintenance operation. It is not part of first paint or the foreground posting contract.

Receiz can therefore store, reopen, project, and extend million-object proof state without treating a database as proof authority. Database and object-storage services remain useful for subordinate coordination, discovery, transport, and projection, but the proof object carries the settled truth.

## Economy Concurrency and Recovery

- Economy head advancement uses compare-and-advance semantics.
- The first economy append bootstraps atomically from a `null` active pointer even when a verified genesis or legacy sealed head already exists.
- Later appends compare the exact active digest against their predecessor.
- Overlapping sibling appends cannot silently replace one another. Conflicts retry or enter verified merge/reconciliation.
- Recovered historical economy members require sealed history or membership evidence; count and direct-child checks alone are insufficient.
- Market projection selects the newest verified descendant for each stable profile identity rather than retaining the first historical version.
- Projection rebuild remains exact-digest and derivative.

## Visibility, Signed Originals, and Public Projection

- Signing an already-published Original refreshes the canonical public and Market projections.
- Stable signed-artifact download routes are persisted instead of expiring signed URLs.
- Hide and re-show operations update the published projection and append the matching bounded showcase/economy transition.
- Hidden-Original recovery follows pagination rather than assuming the first owner page contains the target.
- Repeating an already-hidden request is an idempotent successful transition.
- Updating an existing Original preserves canonical creation ordering instead of moving it to the top.
- Composer PNG children are projected through their actual sealed child payload contract; JSON-only test assumptions cannot erase normal published Originals.

## Identity Custody and Verification Memory

- Identity custody retains proof authority only for the active accepted session/account.
- Explicit logout clears the held Identity Record key file and passphrase closure.
- Slow legacy custody finalization runs outside successful sign-in navigation.
- Every async custody admission is generation-bound. Logout or a newer admission invalidates the older finalizer, so stale work cannot repopulate cleared signing custody.
- Device-certificate verification and imported Ed25519 key caches are bounded.
- Invalid certificate results are not retained without limit.

These changes preserve the Identity Record as the authority while preventing session mechanics and long-lived runtime memory from extending that authority beyond its accepted boundary.
