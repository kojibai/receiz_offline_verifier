# Receiz v120.0.0 Release Process

Developer surface: `@receiz/sdk@120.0.0`. Durable proof-memory law: first admission only, then append forever.

## Goal

Freeze one coherent v120 subject, Twin, world, mandate, runtime, bearer-transfer, narration, SDK, MCP, AI Skills, emulator, conformance, and documentation release without weakening sealed proof authority or deterministic first paint.

## What Worked

1. Freeze the exact v120 registry, operation matrix, reducer digest, schema inventory, package identity, AI catalog, and MCP inventory.
2. Run the focused SDK/MCP living-subject tests and 19-check conformance suite.
3. Run profile, Twin, long-form, narration, first-paint, continuity, and visible browser checks against the same candidate tree.
4. Run coordinated identity, AI distribution, SDK package, MCP package, Academy archive, governance, build, performance, and full release-freeze gates.
5. Generate and independently verify the signed attestation only after every required gate passes.
6. Publish packages, deploy, generate any approved production narration inventory, and record production smoke as separate evidence. None is inferred from repository tests.

## What Did Not Work

A fixed 96-object prompt window could not represent complete proof history, stale package/service-worker release pins could not satisfy coordinated identity, and narration readiness could not be inferred when production contained no exact-digest audio artifact. The production narration backfill also cannot be performed without explicit authorization for the TTS disclosure and production writes.

## Practical Rule For Future Work

If any exact head, namespace byte, authority digest, event citation, replay head, visible count, play-control state, or package identity differs, stop. Repair the implementation or candidate artifact; do not weaken the contract.
