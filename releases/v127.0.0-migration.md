## Local proof creation and custody

The new public SDK entry points are `@receiz/sdk/offline`,
`@receiz/sdk/offline/node`, `@receiz/sdk/offline/kai`,
`@receiz/sdk/offline/kai/node`, and `@receiz/sdk/subjects/node`.
Follow the [offline sealing guide](../../packages/receiz-sdk/docs/offline-sealing.md)
for exact imports, proof resources, enrollment, verification and MCP commands.

File sealing requires explicit one-time online enrollment of a device-generated
key. Retain private signer custody and the canonical proof resources locally.
After enrollment, sealing and verification run without network calls, including
after restart. Missing enrollment fails explicitly; sealing does not silently
enroll. Browser custody is origin-scoped and does not transfer from another
origin. Node uses private local custody. Save and reopen the exact output bytes.
Local KaiSigil proving uses its separate canonical circuit resources and requires
no enrollment or network; bare pulse values cannot substitute for full proof.

MCP uses `RECEIZ_OFFLINE_SEAL_DIRECTORY` for private custody and
`RECEIZ_OFFLINE_WORKSPACE` for source/output files. Follow the guide for the
explicit enrollment tool, readiness, sealing, verification and KaiSigil tool.
Neither an AI instruction nor a signing certificate establishes owner identity,
transfer permission or Settlement authority.

## Subject protocol and HTTP compatibility

Use the shipped local host from `@receiz/sdk/subjects/node` with an admitted
Identity Record and enclosing sealed V120 source. The [local subject guide](../../packages/receiz-sdk/docs/local-subject-runtime.md)
provides the exact SDK options and MCP environment settings. Existing durable
state, exact source artifacts and full temporal evidence survive restart.
Seal portable exports before import; bare JSON is not an admission boundary.

V120 subject identity and history retain their exact protocol. Modern V122
admission/state APIs remain separate; do not reinterpret or remint a V122 head
as V120. Historical bearer transport requires its existing shared ownership and
single-use custody domain; copying a snapshot cannot create that domain.

Historical Connect HTTP methods require both an explicitly configured custom
implementing host and `legacyConnectTransport: "http"`. MCP selects the same
boundary with `RECEIZ_BASE_URL` and `RECEIZ_LEGACY_CONNECT_TRANSPORT=http`.
Credentials alone do not enable absent default routes. Follow the [HTTP
execution guide](../../packages/receiz-sdk/docs/historical-http.md); do not map
historical JSON onto canonical identity, ownership or Settlement authority.
The offline sealer and shipped local subject host need no historical HTTP host.
