# Receiz v125.0.0 Regression Lessons

**Reality-Grade Infrastructure — source + law + sequence + object + evidence. Then the reader.**

The hardest v125 failures were not missing features. They were moments where a representation, timestamp, partial payload, background reconciliation, or generated artifact was allowed to behave as though it outranked the proof object.

The public `@receiz/sdk` contract preserves durable proof memory as **first admission only, then append forever**.

## What Regressed

- A self-authored grant proves only that a subject authored bytes; it does not prove that an authorized domain authority granted a role.
- Formatted evidence digests do not satisfy evidence requirements until the referenced sealed proof objects are opened and verified.
- An unkeyed event digest does not prove who authored an attestation event; actor proof must cover the exact event and prior head.
- A current grant-revocation list cannot invalidate events that were lawful before the revocation append became effective.
- A credential identifier cannot substitute for the exact predecessor lifecycle head in renewal or replacement.
- Application, evidence, evaluation, approval, and issuance coordinates must remain causal and must respect the application deadline.
- A number labeled `kai_upulse` is not KKS authority. It must arrive through the proof-bearing KKS/KaiSigil boundary and strictly advance its retained head.
- `createdAt`, database clocks, filenames, labels, and presentation claims cannot decide causal order or identity-artifact membership.
- A locally sealed Showcase append cannot disappear while the server rediscovers it; global sync extends the same object.
- Repeated identity activity may remain available to continuity logic without appearing as duplicate public Identity Seals.
- The Creation Sigil cannot be removed while waiting for a richer coordinate. Its carried original pulse must project everywhere it is rendered.
- A public SDK or MCP client must reject every non-success HTTP response even when the body is valid JSON.
- Published MCP `dist` is executable release code and must be regenerated from corrected source.

## Why It Regressed

- A current-release manifest cannot remain on a predecessor schema or compatibility range after package promotion.
- An OIDC catalog must carry every scope and registered-origin binding exposed by the SDK routes.
- A current inventory digest follows exact source order; a separately assembled projection can drift.
- An untracked repository-local pnpm store can block the registry's Git-clean publish check even when packaging succeeds.
- Exact dependent packages can briefly become uninstallable when their exact dependency has not yet published; publish dependency-first and verify a clean external install.
- Focused suites can pass while the umbrella release gate still detects historical, generated-output, first-paint, or distribution drift.
- A failed transactional SQL batch may leave the database unchanged; verify the resulting schema, not the attempted command.

## Locked Rules

- First admission only, then append forever.
- Source → evidence → relationship → permissible inference → representation. Never backward.
- Chronos describes; Kai orders.
- The enclosing proof object is authority; embedded projections remain subordinate.
- Existing lawful identity, custody, and history are preserved; correction is an append, never a rewrite.
- No institution, government, database, server, model, or UI receives an authority exemption.

## Contract Gates

- `pnpm test:release-freeze` is the umbrella release boundary.
- `pnpm test:showcase-value` freezes exact projector identity and integer value reproduction.
- `pnpm test:temporal-authority-conformance` freezes KKS/KaiSigil admission and Chronos subordination.
- `pnpm test:coordinated-package-release` freezes SDK, MCP, AI Skills, packed docs, exports, and release identity.
- `pnpm governance:check`, `pnpm governance:evidence-check`, and `pnpm governance:verify-artifact-signature` remain independent required governance evidence.
