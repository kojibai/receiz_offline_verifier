# Receiz v116.0.0 Regression Lessons

@receiz/sdk preserves durable proof memory: first admission only, then append forever.

## What Regressed

- A returning owner projection could briefly erase accepted PBI proof.
- Metered and paid-credit routes missed lifecycle inputs or reconciliation.
- First-use guidance led with optional Twin setup.

## Why It Regressed

Equal-rank UI projection outranked accepted proof, and route-specific payment
paths did not carry the full settlement context.

## Locked Rules

- A signed term must reach every metered Business execution path.
- Paid credit settlement must follow the complete Stripe event lifecycle.
- Hosted checkout return must reconcile before presenting a final balance.
- An unsigned owner projection may enrich a profile but never erase accepted
  PBI proof.
- First-use guidance must begin with creation, not optional Twin setup.
- Warning cleanup may remove noise; it may not change product logic.

## Contract Gates

Focused identity, Creator, dispute, checkout-return, setup-copy, first-paint,
lint, build, and release-freeze contracts must pass.

## Release-Lock Requirement

This record is mandatory release evidence. An unsigned owner projection cannot
erase accepted PBI proof, route-specific execution cannot omit a signed term or
settlement lifecycle input, checkout return cannot present stale paid-credit
truth, and first use cannot make optional Twin setup a creation prerequisite.
