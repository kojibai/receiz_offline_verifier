# Receiz v116.0.0 Process

@receiz/sdk preserves durable proof memory: first admission only, then append forever.

## Goal

Promote the current baseline. Change no settled logic or experience beyond the
named copy and regression fixes.

## What Worked

- Coordinated `116.0.0` identity across app, packages, verifier, skills, and
  service worker.
- Immutable v115 predecessor and additive v116 registry.
- Pure local PBI proof preservation.
- Composer-first setup copy.

## What Did Not Work

The dependency tree was removed by an incomplete offline install. Full gates
cannot run until the frozen lockfile is restored.

## Practical Rule For Future Work

Promote release identity mechanically. Change product behavior only behind an
exact regression contract.

## Required Proof

- Full release freeze with no actionable warnings.
- Governance controls.
- Generated and independently verified release attestation.
- Visual evidence for the owner setup sequence and returning PBI badge.

The v117 program remains deferred.

## Release-Lock Requirement

The standalone release lock must require this process, product truth,
regression lessons, performance findings, invariant register, commit-history
boundary, registry JSON/digest, SQL/history distinction, missing upstream
dependency limitation, and v117 planning deferral. Passing local static gates
cannot change any unchecked upstream or external gate.
