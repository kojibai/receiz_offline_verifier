# Receiz v125.0.0 Conformance

A v125 implementation conforms only when the same authority order survives direct SDK use, transport, persistence, MCP, AI operation, public presentation, and recovery.

## Required invariants

- The current release, registry, operation matrix, packages, generated clients, and published inventories resolve to `125.0.0`.
- The enclosing sealed artifact verifies before an embedded law, action, identity claim, grant, evidence reference, credential, or value payload is parsed as authority.
- A Kai coordinate is admitted only through its proof-bearing KKS/KaiSigil boundary and exact basis; bare decimal strings and Chronos projections fail closed.
- Live coordinates are strictly monotonic even for multiple appends inside one millisecond or a backward wall-clock sample.
- Every append binds its exact prior head; equal, decreasing, future, retrocausal, stale, conflicting, or branch-substituted coordinates fail before mutation.
- Role grants bind an authorized grantor, not the subject's own self-hashable namespace.
- Every attestation event carries Receiz ID/PBI authorship over the exact event payload and previous head.
- Referenced evidence proof objects verify subject, custody, content commitment, verifier binding, and collection coordinate before satisfying a minimum.
- Expired applications admit only deterministic expiry; renewal and replacement bind the exact predecessor lifecycle append; revocation is effective prospectively from its coordinated head/Kai.
- Settlement value is recomputed from sealed Kai coordinates; no caller may supply an amount, multiplier, bonus, backfill, or institutional exemption.
- The sealed Showcase known-answer vector resolves to `13,379,717` micro-Phi and projector digest `c04c6a1d2b6e843134460318212a43386f15f585b157bf86aa4f2a28a776e38c`.
- One membership belongs to exactly one current owner; custody moves membership and preserves all provenance.
- Sender and receiver independently verify the same committed two-party transition at their edges.
- Duplicate, replayed, stale-head, ownership-conflicting, invalid-proof, invalid-origin, or invalid-value requests write zero.
- Known verified local truth paints before synchronization; background work may append verified additions but cannot replace the settled object.
- MCP never exposes artifact bytes, a bearer, private key, runtime brand, or authority material to model context.
- Non-success HTTP responses reject through both the framework-neutral SDK client and MCP transport.
- V119–v124.1 historical locks continue to pass without modified historical bytes.

## Evidence rule

A passing source suite proves the tested source tree. It does not by itself prove package publication, production schema, public deployment, Git tag, Docs deployment, or release attestation. Those coordinates are recorded independently in [evidence status](v125.0.0-evidence-status.md).
