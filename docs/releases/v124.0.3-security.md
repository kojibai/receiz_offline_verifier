# Receiz v124.0.3 Security — Reality Becomes Infrastructure

Release date: August 25, 2026

**The Production Runtime for Verified Civilization.** Security keeps source bytes and the sealed proof object above export representations, packages, tags, segment stores, URLs, QR codes, previews, servers, databases, sessions, deployments, and model output under ruleset `124.0.0`.

## Exact-byte and continuity boundary

- Verification acceptance requires integrity, payload/current-basis equality, denial clearance, and valid native ownership and historical continuity.
- `verification.ok` alone cannot authorize a surface verdict.
- When native Record/Seal ownership identifies a different basis than the current artifact, verification rejects with `continuity_ownership_attestation_mismatch`.
- A PBI authorship append binds presence-bound authorship to the exact predecessor and creates an exact separately verified descendant without ownership transfer.
- Exporting that descendant cannot rewrite pixels, inject a badge, normalize bytes, or invoke an export-only verifier exception.
- Generic streaming results require runtime proof-bundle validation; a TypeScript assertion cannot upgrade generic data into proof truth.

## Resource and offline boundary

- Large Record, Seal, Verify, Append, and PBI operations hash/read source ranges incrementally and avoid optional playback materialization.
- Resource exhaustion, worker unavailability, timeout, or browser reload is an execution failure and never an invalid-proof verdict.
- The standalone offline verifier and Offline Studio verify held artifact bytes without account, session, database, server, object store, or network authority.
- SDK, MCP, AI Skills, Workbench vendor files, compact links, and QR codes are coordinated mechanics only.

## Playback and public proof boundary

- Inline material is accepted only after its enclosing carried proof verifies.
- `rmc1` segments are accepted only through exact ordered commitments and complete proof-object verification; segment custody never becomes authority.
- Profile playback and global sync remain presentation/publication beneath admitted proof objects. The working image/audio path is not weakened to repair video.
- The `/v` label **Proof** follows successful carried-bundle verification; copy cannot upgrade an unverified coordinate.

## Residual security evidence

No claim is made about package publication, Git tag immutability, production deployment, authenticated production mutation smoke, live mobile memory behavior, load scale, adoption, or institutional/government approval. Those require separate evidence and still cannot replace sealed artifact truth.
