# Receiz v119.0.0 Release Lock Checklist

Package surface: `@receiz/sdk@119.0.0`. Durable proof-memory law: first admission only, then append forever.

Bound records: [docs/releases/v119.0.0-product-truth.md](v119.0.0-product-truth.md), [docs/releases/v119.0.0-regression-lessons.md](v119.0.0-regression-lessons.md), and [docs/releases/v119.0.0-commit-history.md](v119.0.0-commit-history.md).

## Coordinated identity

- [ ] V119 constitution registry directly names the immutable v118 digest.
- [ ] SDK, MCP server, AI skills, verifier bindings, operation matrix, package
      versions, manifests, generated files, and release notes are exact.
- [ ] One coordinated identity gate fails on any mismatch.

## Recursive continuity

- [ ] Highest valid Kai selects every active domain and global head.
- [ ] Merkle roots commit exact appends.
- [ ] Fibonacci logs contain exact sparse checkpoints with externally resolved
      ancestry.
- [ ] Equal-Kai divergent heads fail closed.
- [ ] Lower-Kai server/database/session responses cannot replace held truth.
- [ ] Million-event append vectors remain bounded and do not replay history.

## Durable device truth

- [ ] PWA close/reopen preserves all immutable proof objects and segments.
- [ ] Service-worker update deletes no IndexedDB/local proof database.
- [ ] Active projections and immutable artifact stores are separate.
- [ ] Storage migrations are additive and never delete predecessor artifacts.
- [ ] First-paint handoffs contain verified settled heads, not defaults.

## Qualified Offline Note custody

- [ ] Transferable Note genesis starts from the canonically verified
      `receiz.account.state.v3` Receiz Key/Identity proof and its exact Reserve
      head.
- [ ] The external funded event is sealed into
      `receiz.offline-reserve.funding-binding.v1` against that exact account
      head and preselected qualified Reserve custody before the Reserve can
      authorize Offline Note issuance; legacy/unbound Reserve fails closed.
- [ ] One local issuance composes one Reserve-debit account-state successor and
      one equal whole-value qualified held-bound Note genesis.
- [ ] Both successors canonical-verify before that exact Note genesis activates
      in qualified irreversible custody.
- [ ] Supabase, server, database, session, and publication are optional later
      projection only; none gates or releases the Note, authorizes issuance,
      establishes Settlement, or replaces the carried Reserve proof.
- [ ] Cash Send requires no username, Receiz ID, PBI, account, session, server,
      database, or publication authority.
- [ ] Every Send canonical-verifies the enclosing exact head before custody
      consumption.
- [ ] Every successful consumption binds the exact predecessor digest,
      expected and consumed irreversible state, receiver commitment, whole
      value, Kai position, and complete successor basis.
- [ ] One consumed head cannot authorize a different or repeated successor.
- [ ] No successor bytes are released before irreversible consumption succeeds
      and the final successor canonical-verifies.
- [ ] The receiver activates only the exact successor bound to its qualified
      anonymous custody commitment.
- [ ] Receiver activation completes local Settlement without server,
      database, global sync, or publication.
- [ ] The predecessor remains verifiable history and permanently loses Send
      authority.
- [ ] Missing, repeated, decreased, unexpectedly advanced, restored,
      backup-eligible, malformed, or crash-inconsistent custody state fails
      closed.
- [ ] Unqualified installations retain canonical Verify and separately
      governed connected Send, but cannot create, receive, activate, or Offline
      Send transferable Notes.
- [ ] Production qualification is backed by exact registered physical-profile
      evidence; generic browser, passkey, platform, model, or account claims do
      not qualify.
- [ ] Optional identity lock remains one-handoff policy beneath anonymous Cash
      Send and cannot become transition authority.
- [ ] Publication stores/distributes verified evidence without using arrival
      order, a database row, or server response as Settlement authority.

## Offline Note developer parity

- [ ] SDK public exports include qualification, anonymous receiving-custody,
      WebAuthn consumption/activation, and custody-conformance schemas and
      strict verifiers.
- [ ] SDK public exports include the exact Reserve funding-binding and
      irreversible Reserve split schemas and strict verifiers.
- [ ] Developer guidance verifies the `receiz.account.state.v3` source and the
      paired local Reserve-debit and held-bound Note successors before custody
      activation.
- [ ] CLI documentation states that inspection is not Offline Note custody or
      Send authority.
- [ ] HTTP documentation keeps verification/publication subordinate to local
      Settlement.
- [ ] MCP documentation exposes no second Offline Note authority and routes
      enclosing artifact verification through the SDK.
- [ ] AI documentation requires exact verifier evidence and refuses to infer
      qualification, custody, ownership, or Settlement from model output.

- [ ] Sports source and route performance budgets remain within the frozen UX.
