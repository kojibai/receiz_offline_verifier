# Receiz v125.0.0 Governance Record

## Governing frame

**Reality-Grade Infrastructure — source + law + sequence + object + evidence. Then the reader.**

The governing direction is `source → evidence → relationship → permissible inference → representation`. Release governance is one reader of that stack. It cannot elevate a checklist, approval, package, database row, Git tag, signature, organization, institution, or government above the sealed proof objects and executable laws being released.

## Change authority

- Current release identity is generated from one canonical release record.
- Historical registries, digests, schemas, proof bytes, and release records are immutable.
- New v125 behavior is additive and must preserve the stronger/weaker truth hierarchy.
- A code-review approval does not override a failing invariant, contradictory visual evidence, or weaker first paint.
- Security changes reuse the canonical verifier and existing identity, custody, KKS, and proof-object primitives. A second authority is forbidden without proving the existing primitive cannot carry the boundary.

## Required controls

- Release identity and historical release locks.
- Deterministic surface, first-paint, continuity, profile, identity, World, market, wallet, and public-proof contracts.
- Artifact binding, document seal, temporal authority, issuance, verification, Settlement, sports, and signal-circuit conformance.
- SDK/MCP/AI package coordination and installed-package behavior.
- Governance charter, evidence, artifact-signature, change-control, incident, key-custody, historical-continuity, and independent-assurance controls.
- Production build, lint, performance budgets, and full release freeze.
- External evidence recorded only after direct observation.

## Public assurance surface

The `reality-grade-infrastructure` repository is generated from an explicit allowlist. It publishes SDK, MCP, AI Skills, constitutional verifier, public doctrine, governance standards, conformance material, and v125 release evidence. Every projected file has a SHA-256 digest; the manifest binds the source revision, projection policy, complete file set, and tree digest. Unmanifested, changed, missing, excluded, secret-pattern, and symlink content fails verification.

The public repository welcomes issues and pull requests for correctness, interoperability, conformance, documentation, and implementation. Security reports go through private GitHub Security Advisories. Accepted public changes return through the private release source and normal governed release process; a public-repository merge does not independently create a Receiz release.

## Separation of evidence

- Tests prove the source paths and fixtures they execute.
- Registry metadata proves published package coordinates and recorded bytes.
- Catalog inspection proves observed production schema.
- HTTP smoke proves the listed public response.
- Git tag proves a named immutable source coordinate after it exists.
- Attestation proves the declared evidence bindings after it is signed and independently verified.

None of these evidence classes is allowed to imply another. See [evidence status](v125.0.0-evidence-status.md) for the current release boundary.
