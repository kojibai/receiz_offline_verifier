# Receiz v115.0.0 Process

The public package is `@receiz/sdk`. Durable proof memory remains
**first admission only, then append forever**.

## Goal

Add native photo/video capture and verified offline PBI authorship without
changing the frozen v114 first-seal, ownership, media, verification, or
first-paint laws.

## What Worked

- Binding new truth beneath the canonically verified enclosing artifact.
- Reusing Signature V4, WebAuthn/PBI, Receiz ID, format-preserving carrier,
  canonical verifier, and durable outbox primitives.
- Test-first schema, mutation, source-contract, and release-lock boundaries.
- Real WebKit-generated successors reopened through the actual file chooser.
- One coordinated v115 registry/package/runtime/service-worker promotion.

## What Did Not Work

- Treating a one-pass outbox snapshot as a complete active flush.
- Normalizing corrupt durable outbox bytes to an empty queue.
- Permissive VM-only signing evidence as the sole release qualification.
- Mechanically changing “current” labels without updating the package-current
  registry predecessor verifier.
- Assuming package identity was coordinated before checking committed dist,
  docs, verifier labels, and service-worker identity together.

## Practical Rule For Future Work

Verify the stronger enclosing artifact first. Append one exact scoped proof.
Verify the successor before exposing it. Settle locally before weaker
publication. Preserve every prior byte and history entry. Promote every
coordinated package/runtime surface under one release lock, while leaving
historical registries and proof objects immutable.

## Release-Lock Requirement

The standalone release lock must require this process, product truth,
regression lessons, performance findings, invariant register, commit-history
boundary, registry JSON/digest, and physical-device evidence limitation. Local
qualification cannot complete any SQL or external action.
