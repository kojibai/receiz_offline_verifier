# Receiz v115.0.0 Performance Findings

The public package is `@receiz/sdk`. Durable proof memory remains
**first admission only, then append forever**.

## Media And Carrier Work

Native Capture binds the exact camera-returned source bytes. Photo with text
adds a visible caption while retaining recoverable source truth; video with or
without text preserves the original playable, untranscoded video carrier.
Ordinary upload remains outside Native Capture provenance.

Canonical predecessor verification occurs before PBI signing. Successor
download remains unavailable until canonical successor verification passes.
This is required proof work, not a background projection optimization.

## Local Settlement Bound

Successful PBI authorship settles locally before optional network publication.
The outbox preserves every pending proof without count caps or eviction and
compacts only exact acknowledged reconciliation.

An active flush uses bounded quiescence:

- it drains proofs admitted during the current flush
- overlapping callers coalesce under the active flush
- hostile or non-quiescent producers cannot force an infinite foreground loop
- remaining verified work stays durable for a later retry

The bound limits one flush attempt; it does not authorize dropping pending
proof memory.

## Failure Work

Corrupt durable payloads fail closed with zero writes. Treating corrupt bytes
as an empty queue would be fast but false, so it is forbidden. Publication
failure remains weaker than accepted local proof and cannot delay or revoke
offline completion.

## Verification Projection

Standalone verifier, Offline Studio, and `/verify` project the same
enclosing-artifact-first truth: Signature V4, Groth16, artifact/payload
binding, Native Capture when present, ordered PBI history, and ownership
continuity without an invented transfer.

No Studio-only trust root, allowlist, issuer, or bypass may create a faster
parallel verifier.

## Evidence Boundary

Real WebKit evidence proves two format-preserving PDF successors, zero network
calls, canonical file-chooser reopen, Signature V4, Groth16, and two ordered
PBI appends. It does not prove physical Face ID or the native iOS chooser.

The standalone repository’s lint/build/release-lock gates qualify its current
static distribution only. They do not substitute for the upstream suites,
SQL execution, attestation, publication, deployment, or production evidence.

## Release-Lock Requirement

`pnpm release:lock 115.0.0` must require this record. No future change may
trade exact source-byte preservation, fail-closed durable reads, verified
successor gating, or complete pending proof memory for lower latency.
