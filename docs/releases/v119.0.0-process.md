# Receiz v119.0.0 Release Process

V119 is admitted as the current repository release only when the coordinated release lock, package tests, canonical verifier contracts, Offline Note custody contracts, Academy archive validation, governance controls, and full release freeze pass for the same candidate tree.

The public SDK surface is `@receiz/sdk@119.0.0`.

## Goal

Admit one coordinated v119 candidate that closes the Offline Note custody law,
preserves every prior proof boundary, and exposes one exact SDK/MCP/AI and
Academy release identity.

## Construction

1. Preserve the v118 registry and all historical evidence unchanged.
2. Generate the v119 registry as an append whose predecessor digest is the exact v118 digest.
3. Promote release identity, ruleset, current registry, application matrix, SDK, MCP, AI skills, and verifier manifests together.
4. Regenerate Academy release and developer projections from those current sources.
5. Run package, conformance, governance, and release-freeze gates.
6. Emit attestation only after the gates pass for the bound candidate.

The durable proof-memory law remains first admission only, then append forever. Release projection cannot replace sealed proof-object truth.

Git tag, package publication, deployment, production smoke, production device qualification, and attestation are recorded only after they occur. One dimension never implies another.

## What Worked

Existing Receiz proof primitives composed directly: the verified account-state
Reserve predecessor, canonical sealed Note, Kai ordering, irreversible custody
receipts, durable local admission, and coordinated developer rails.

## What Did Not Work

Identity naming, server arrival, database claims, generic WebAuthn presence,
and caller-shaped device labels could not establish once-only offline custody.
They remain optional projection or mechanics.

## Practical Rule For Future Work

Start from the strongest implemented proof object, remove every non-authority
dependency from the hot path, fail closed at any missing irreversible boundary,
and require the coordinated release lock before calling a candidate attested,
published, deployed, or live.
