# Receiz v124.0.0 — Reality Becomes Infrastructure

**The Production Runtime for Verified Civilization.** V124 is the coordinated production-runtime release for universal Receiz primitives. The sealed proof object remains storage and continuity authority; exact authenticated heads remain execution and replay authority. Servers, databases, sessions, SDK projections, and network operators coordinate beneath that truth and never become its source.

Release date: August 22, 2026

Durable proof memory remains first admission only, then append forever. The coordinated package surface is `@receiz/sdk`, `@receiz/mcp-server`, and `@receiz/ai-skills`, all identified as `124.0.0` with current application compatibility `>=124.0.0 <125.0.0`.

## Release outcomes

V124 makes production deployment structurally harder to misconfigure. Applications can derive canonical live Kai coordinates from pulses since genesis, create whole-pulse proof-authority challenges, bind short-lived execution sessions to application audience and exact proof authority, stage durable plans, execute once, recover by idempotency key, admit only verified replay/checkpoint additions, filter private additions before hydration, commit multi-domain world and inventory effects atomically, resolve recipients without exposing directory enumeration, and report whether required dependencies are operational rather than merely present.

- Canonical live Kai exposes exact whole-pulse and micro-pulse coordinates derived from pulses since genesis through the existing phi-exact ties-to-even bridge.
- Proof-authority challenges bind application, artifact digest, exact scopes, consent digest, bounded whole-pulse lifetime, and nonce without reinterpreting V123 fields.
- One runtime factory binds existing proof authority, subject ownership/head, namespaces, revocation, durable journal/checkpoint, plans, transaction context, private access, and recipient resolution.
- Runtime sessions and every returned result bind the exact application audience, originating request, proof authority, and authenticated head.
- Durable server-side plans support stage, exactly-once execute, cancel, terminal outcome resolution, and recovery by semantic idempotency key.
- Replay and checkpoint verification returns only fully validated additions and namespace metadata; unknown discriminators and statuses fail before callbacks.
- Access-filtered hydration prevents unauthorized private additions, coordinates, membership, or plaintext from reaching the caller.
- Atomic world, inventory/material, Settlement, and Reserve transaction effects advance every declared participant head or write zero accepted state.
- Privacy-safe recipient resolution is consent-bound, rate-limited, non-enumerable, and subordinate to the enclosing transfer proof object.
- Capability descriptors distinguish configured presence from evidenced operational readiness for every required production dependency.

The implementation remains universal. V124 creates no consumer-specific application identity, issuer, admission path, or authority tier. Existing application/principal admission remains unchanged.

## Why it matters

V124 removes ambiguity between representation and reality. A deployer no longer needs custom ports that accidentally duplicate execution, split a transaction, admit unverified replay, retain stale authority, expose private coordinates, enumerate recipients, or report a configured-but-inoperative dependency as production-ready. Verified reality can coordinate durable execution without granting unilateral jurisdiction to an application, institution, server, database, SDK, or network operator.

## Authority boundary

- The sealed proof object and its enclosing verifier remain the strongest portable truth.
- Exact authenticated heads bind accepted continuity, namespace state, replay, and committed outcomes.
- Live Kai is derived from pulses since the canonical genesis through the existing phi-exact ties-to-even bridge; UTC is an observation used to calculate elapsed pulses, not authority.
- V123 whole-pulse `issuedAtKai` fields retain their meaning. Explicit micro-pulse fields use a newly versioned schema and are never retroactively reinterpreted.
- Hosted journals, checkpoints, plans, sessions, and database rows are durable sync, coordination, and recovery surfaces beneath proof/head authority.
- Public root runtime and execution transports fail closed when request-bound authenticated proof/head evidence is unavailable.
