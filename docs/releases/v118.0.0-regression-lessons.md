# Receiz v118.0.0 Regression Lessons

Public developer surface: `@receiz/sdk` v118.0.0. Durable proof memory remains
**first admission only, then append forever**.

## What Regressed

### A package version is not a coordinated release

V117 demonstrated that matching `117.0.0` labels can conceal different embedded
operation matrices. Version strings, generated files, and package manifests are
projections—not evidence of equality. V118 recomputes content digests and
compares runtime values, source manifests, and packed tarballs.

## Why It Regressed

### The release gate must precede publication

A post-release mismatch report is too late. SDK, MCP, and AI now run the
coordinated identity check during packing and publication. The umbrella freeze
runs it before package distribution tests. Mutation tests prevent a future
maintainer from accidentally weakening the comparison.

## Locked Rules

### A transaction image must carry transaction truth

A beautiful image, self-hashable JSON, or working QR is not transaction proof.
The exact existing transaction proof object must remain embedded, and the
enclosing artifact must bind it. Verification starts with the stronger artifact
and only then projects the transaction. The verifier did not need a special
case because the artifact was corrected to obey the existing law.

### “Already sealed” means append, not reseal

Collection failed when it treated an existing transaction as input to a new
transaction-sealing ceremony. V118 retains the transaction and adds the visual
moment as an artifact append. This preserves identity, history, and offline
verification while eliminating the false “failed to seal” state.

### Logged-out absence is not unavailable settlement truth

An unauthenticated wallet has no admitted account settlement state, but its
display value is still truthfully `$0`. “Unavailable” implied a broken system.
The fix is narrowly scoped to auth-required state so it cannot overwrite known
signed-in settlement truth.

### Conformance must be visible where doctrine is used

Runbooks and proof-native labels should lead to their evidence. Links and
badges remain subordinate navigation; they must not restyle or replace the
settlement primitive they explain.

## Contract Gates

### Complete history needs two layers

A raw commit ledger is necessary for auditability but insufficient for
understanding. A polished narrative is necessary for meaning but insufficient
for completeness. V118 ships both and clearly separates implemented work from
v119 planning.
