# Receiz v115.0.0

Release date: 2026-07-29

Receiz v115.0.0 adds native photo/video provenance and offline PBI authorship
to the existing Record, Seal, and canonical verification system. The enclosing
sealed artifact remains authority. Native Capture and authorship are verified
proof-object appends beneath it; neither creates a parallel proof chain.

Release baseline: v114.0.0 at `1b4ff9d4a`.

The public developer package is `@receiz/sdk`. Durable proof memory remains
**first admission only, then append forever**.

## Native Capture

Offline Studio now exposes one Native Capture control. The operating-system
camera ceremony selects Photo or Video.

- `receiz.native_capture.v1` binds the exact camera-returned source bytes,
  media kind, MIME type, dimensions/duration, ceremony commitment, Receiz ID,
  proof coordinates, and Kai time.
- An ordinary upload or file-picker selection cannot acquire Native Capture
  provenance.
- Native Capture attests Receiz's dedicated camera ceremony. It does not claim
  physical-sensor certification.
- Photo-only preserves the captured photo as carrier.
- Photo plus text renders a visible caption while retaining the exact captured
  source bytes as recoverable enclosed truth.
- Video-only and video plus text preserve the original playable, untranscoded
  video carrier. Caption text is embedded without replacing the video.
- Text-only keeps the frozen v114 Record behavior.

## Verified Offline PBI Authorship

`receiz.pbi.proof-object-authorship.v1` appends PBI authorship only after the
predecessor artifact passes the canonical verifier.

Each append binds:

- exact predecessor artifact SHA-256 and proof head
- position and previous append head
- claim hash and proof coordinates
- Receiz ID and credential identity
- verified PBI receipt
- Kai/Chronos event

Multiple signers append in deterministic order forever. Signing never changes
ownership, custody, media bytes, Native Capture provenance, or prior proof
history. The downloaded successor remains unavailable until that successor
passes canonical verification.

## Offline Settlement and Global Propagation

Successful authorship settles locally first. Network publication is a weaker,
optional propagation step. The durable local outbox:

- fails closed on corrupt durable payloads with zero writes
- preserves every pending proof without caps or eviction
- drains proofs admitted during an active flush
- bounds hostile/non-quiescent producers
- compacts only exact acknowledged reconciliation
- retries publication without delaying offline completion

These rules apply equally to the embedded Studio path and shared app path.

## Canonical Verification

The standalone verifier, Offline Studio verifier, and `/verify` project the
same enclosing-artifact-first truth:

- Signature V4 and Groth16
- artifact/payload binding
- Native Capture provenance when present
- complete ordered PBI authorship history
- ownership continuity without inventing an authorship transfer

Offline Studio executes the exact canonical standalone verifier runtime. No
Studio-only root, issuer, allowlist, or bypass was added.

## Frozen v114 Continuity

V115 does not rename or mutate the v114 profile/economy proof objects. First
seal, ownerless genesis, later ownership append, cross-surface continuity,
format-preserving carriers, deterministic first paint, and verifier failure
behavior remain frozen. V115's registry is additive and chains to the immutable
v114 digest.
