# Receiz v124.0.0 Migration — Reality Becomes Infrastructure

**The Production Runtime for Verified Civilization.** No proof-object migration or rewrite is required. Historical sealed proof object bytes remain authority and retain exact V123 semantics.

## Repository migration boundary

The repository includes a candidate durable-runtime SQL migration, but production migration application has not been performed or verified by this release record. Applying that migration is an external operation and requires its own exact project, checksum, rollback, and post-application evidence.

## Adoption actions

1. Upgrade `@receiz/sdk`, `@receiz/mcp-server`, and `@receiz/ai-skills` together to `124.0.0` only after publication is independently confirmed.
2. Set application compatibility to `>=124.0.0 <125.0.0`.
3. Preserve V123 whole-pulse fields and introduce explicit micro-pulse fields only through their new schema.
4. Configure durable journal, checkpoint, plan, revocation, transaction, private-access, and recipient-resolution dependencies.
5. Require operational evidence for every required dependency and fail qualification closed when any evidence is absent.
6. Apply the production migration only through approved deployment tooling and capture its independent evidence.
7. Verify request-bound proof/head authentication before enabling public runtime and execution calls.

Durable proof memory remains first admission only, then append forever. Database rows may synchronize and recover the admitted history; they do not replace the proof object.
