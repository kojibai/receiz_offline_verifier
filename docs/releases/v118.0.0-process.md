# Receiz v118.0.0 Release Process

Public developer surface: `@receiz/sdk` v118.0.0. Durable proof memory remains
**first admission only, then append forever**.

## Goal

Create one indivisible v118 release identity, preserve every stronger proof and
settlement primitive, and make mismatch impossible to publish through the
normal SDK, MCP, and AI package paths.

## What Worked

### Construction

1. Reproduced the v117 SDK/AI matrix mismatch with an independent failing
   contract.
2. Generated one additive v118 registry and canonical SDK release identity.
3. Projected that identity into MCP and all AI manifests from SDK constants.
4. Added a permanent independent validator and mutation tests.
5. Wired the validator ahead of package/distribution checks and into the full
   release freeze.
6. Added prepack/prepublication failure to SDK, MCP, and AI packages.
7. Proved packed runtime parity in a clean consumer without workspace source.
8. Moved all unimplemented orchestration work to v119.
9. Generated the complete Git ledger and wrote the v110→v118 architectural
   record.

## What Did Not Work

### Environment boundaries

The default 4 GiB TypeScript process exhausted memory; the same complete check
passed with `--max-old-space-size=8192`. Registry DNS was unavailable during
one packed-consumer run; the designed offline path used exact tarballs and
locally installed declared runtime dependencies, then passed. These are
tooling/network boundaries, not product-law exceptions.

## Practical Rule For Future Work

Generate current package identity from one canonical registry, recompute it
independently at the release boundary, test deliberate mutations, and qualify
the packed tarballs—not only workspace source—before publication.

### External actions intentionally excluded

No npm publication, push, tag, GitHub signing, deployment, production mutation,
or production smoke is performed by this local release process. The user owns
the push; GitHub owns signing under the repository workflow.
