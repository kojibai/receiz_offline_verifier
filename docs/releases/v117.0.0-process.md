# Receiz v117.0.0 Release Process

## Goal

Lock exactly the implemented post-v116 product and package work as one truthful coordinated v117 release without importing deferred v118 planning.

## Baseline

The immutable baseline is tag `v116.0.0` at commit `8a8a828ec`. The v117 record covers every commit after that tag through the final release-lock commit.

That commit is the coordinated application repository baseline. In this
standalone repository, the immutable local `v116.0.0` predecessor resolves to
`dd46a7bc99d28baf941e361e01ea2b936a7a944a`; the local v117 commit advances the
verifier distribution and mirrors the coordinated release evidence without
rewriting either history.

## Method

1. Inventory all post-v116 commits and classify shipped product behavior, proof-law preservation, release mechanics, and deferred proposals.
2. Reproduce release-gate failures before editing. Change production code where behavior violates law; change tests only where their asserted contract is stale or contradicts law.
3. Keep the release runner exhaustive. A missing isolated profile DB fixture is recorded as unavailable, while every later test still runs. Genuine failures remain release-blocking at final aggregation.
4. Extract the prepared Sports seal-save hook without changing import timing, effect timing, digest inputs, native sealing custody, transfer append, messages, or visible outcomes.
5. Generate v117 as an additive registry whose predecessor is the exact v116 digest and whose laws remain identical.
6. Promote all current app/package/AI/service-worker/offline identifiers together. Preserve v116 identifiers only in immutable historical contracts and predecessor bindings.
7. Move the unimplemented v117 orchestration plan to v118 and leave a historical pointer.
8. Run focused contracts, coordinated package tests, the full release freeze, governance controls, build, visual evidence, and attestation.
9. Only after clean evidence: commit the release lock and create annotated tag `v117.0.0`.

## What Worked

Root-cause triage separated unavailable infrastructure, production defects, stale contracts, and deterministic fixture drift. Additive registry promotion preserved predecessor history. Direct Sports hook extraction reduced source size without changing execution or visible behavior.

## What Did Not Work

The initial release notes did not yet satisfy the repository’s exact release-document headings and link contract. The first coordinated package run correctly exposed a stale v116 AI-distribution test. Both were corrected without weakening product behavior.

## Practical Rule For Future Work

Promote all current package and visible version surfaces together, preserve prior versions only as explicit history, and run the repository lock before attestation. Never treat missing optional infrastructure as permission to skip later gates.

## Authority boundary

Release metadata, registry files, tests, CI, DB fixtures, generated share images, and attestation are evidence or mechanics beneath the sealed Receiz proof object. None becomes product proof authority.

The `@receiz/sdk` v117 public contract preserves durable proof memory as **first admission only, then append forever**.

## Standalone qualification boundary

The standalone release runs its repository release lock, lint/build surfaces,
archive parity, relative-link, registry-chain, and Git-integrity checks. The
application/package release freeze, coordinated-package gates, browser proof,
governance controls, and signed attestation belong to the separate application
repository and remain unclaimed here.
