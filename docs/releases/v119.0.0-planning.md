# Receiz v119.0.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> `superpowers:subagent-driven-development` (recommended) or
> `superpowers:executing-plans` to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Receiz proof orchestration substantially easier, faster, and
more composable without weakening sealed artifact authority, verified local
truth, deterministic first paint, offline operation, ownership continuity, or
settlement law.

**Architecture:** V119 composes the existing v114 profile/economy composite
proof primitives and v115 Native Capture/PBI authorship primitives into
SDK-custodied orchestration. One universal conditional transition engine owns
inspect, plan, authorize, stage, compare-and-swap commit, and receipt
verification; higher-level commerce, projection, realtime, storage, generated
client, verifier, emulator, exchange, React, MCP, and AI surfaces remain
beneath that engine and never become authority.

**Tech Stack:** TypeScript, `@receiz/sdk`, Web Crypto, WebAuthn/PBI, IndexedDB,
Node filesystem adapters, PostgreSQL/object-storage interfaces, Web Workers,
WASM-capable verifier adapters, React headless hooks, MCP, deterministic
emulator traces, Node test runner, and Receiz release/governance gates.

## Global Constraints

- The enclosing sealed Receiz artifact remains the strongest proof authority.
- Verified durable local truth is not cache and must paint before weaker
  network, server, database, or session discovery.
- Durable proof memory remains **first admission only, then append forever**.
- PWA close, reinstall, code deployment, and service-worker activation may
  rotate code/HTTP caches only; they must never delete user proof objects,
  immutable segments, append history, or admission evidence.
- Highest valid Kai selects the active head; Merkle commits exact appends;
  Fibonacci checkpoints provide sparse ancestry. These roles may not be
  conflated.
- Current player rates, scores, values, profile heads, and history counts are
  admitted proof state. They paint exactly on first view and only higher-Kai
  verified successors may update them.
- Existing v114 profile/economy proof objects and v115 Native Capture/PBI
  authorship proof objects remain byte-compatible and historically immutable.
- V119 may add typed builders and orchestration, but callers may never manually
  manufacture operation digests, evidence roots, counters, parent bindings, or
  confirmation receipts.
- A failed verification, admission, authorization, stage, or compare-and-swap
  commit performs no canonical write.
- Economy projection remains a verified projection of admitted proof objects;
  it must never be described or implemented as the authority or as a
  transaction ledger.
- Presence and optimistic intent remain explicitly weaker than durable accepted
  proof state.
- Realtime, storage, React, MCP, and AI surfaces may transport or project
  verified proof; none may issue proof authority.
- Migration must preserve exact pins, application routes, developer-owned
  extensions, generated ownership boundaries, historical evidence, and release
  lock configuration.
- Every new operation requires a failing contract first, a passing focused
  contract second, and the complete release gates before promotion.
- No Wildz-specific authority API may substitute for the universal Receiz
  primitives defined here.

## What V118 Already Settled

V119 must build on the v118 release and these settled primitives rather than reopen them:

- Contacts, Profile, Wallet, Sports, and installed-PWA surfaces preserve stronger held proof truth and deterministic first paint against weaker refreshes.
- `/t/` transaction and adaptable `/v/` public witness moments have proof-native share images and ready-to-send copy outside the hot path.
- An already sealed transaction Moment downloads directly without resealing.
- Sports Arena keeps its full live proof and native-save experience beneath the 500,000-byte source ceiling.
- SDK, MCP, verifier, and AI skills share the coordinated v118 registry, operation matrix, package identity, and publication gate.
- `receiz.native_capture.v1` binds exact camera-ceremony provenance beneath the
  enclosing verified artifact.
- `receiz.pbi.proof-object-authorship.v1` appends ordered verified PBI
  authorship without transferring ownership or rewriting media.
- Offline Studio verifies the predecessor and successor canonically.
- Local proof settlement completes before optional global propagation.
- The durable PBI publication outbox fails closed, preserves pending proof, and
  drains same-run admissions.
- First seal, ownerless genesis, ownership continuity, format-preserving
  carriers, profile/economy composite proof objects, and deterministic first
  paint remain frozen.

## Release Shape

V119 is organized around three required pillars:

1. **Atomicity:** universal conditional multi-proof transitions and
   SDK-custodied commerce orchestration.
2. **Immediacy:** causal proof deltas, worker-based verification, and
   chunk-addressable proof objects.
3. **Creativity:** generated typed clients, deterministic multi-writer
   emulation, safe AI/MCP plans, and portable exchange.

All tasks below are part of the v119 plan. Tasks 1–7 establish the authority
kernel and must settle before tasks 8–15 can be promoted.
